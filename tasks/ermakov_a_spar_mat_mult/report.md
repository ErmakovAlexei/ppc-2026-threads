## 1. Введение

Умножение разреженных матриц относится к базовым операциям научных вычислений и
широко используется в численных методах, обработке графов, задачах оптимизации
и моделировании физических процессов. При разреженном представлении важно не
выполнять операции над нулевыми элементами и не хранить их явно, иначе теряется
основное преимущество sparse-структур.

В работе реализовано умножение матриц с элементами комплексного типа в формате
CRS (Compressed Row Storage) в пяти вариантах: последовательном, на OpenMP,
Intel oneAPI TBB, стандартных потоках C++ и в гибридном варианте ALL
(`MPI + OMP`). Целью работы было получить корректные и согласованные по
результату реализации, а также оценить влияние различных технологий
распараллеливания на производительность.

---

## 2. Постановка задачи

**Вход:** две разреженные матрицы `A` и `B` в формате `CRS`, где:

- `rows`, `cols` — размеры матрицы;
- `values` — ненулевые комплексные значения;
- `col_index` — номера столбцов для значений;
- `row_ptr` — массив указателей на начало строк.

**Условие корректности:** число столбцов матрицы `A` должно совпадать с числом
строк матрицы `B`.

**Выход:** матрица `C = A * B` в том же формате `CRS`.

**Особенности задачи:**

- элементы матриц имеют тип `std::complex<double>`;
- нулевые элементы в результате не сохраняются;
- проверка нулевых значений во всех реализациях выровнена и выполняется через
  точное сравнение с `0 + 0i`.

---

## 3. Описание последовательного алгоритма

Последовательная реализация использует классическую схему умножения `CRS x CRS`
по строкам:

1. Для строки `i` матрицы `A` перебираются все ненулевые элементы `a(i, j)`.
2. Для каждого такого элемента просматривается строка `j` матрицы `B`.
3. Частичные произведения `a(i, j) * b(j, k)` накапливаются во временном
   буфере строки результата.
4. Для исключения полной очистки буфера после каждой строки используется
   маркерный массив `row_mark`: столбец считается активным, если его метка равна
   текущему индексу строки.
5. После обработки строки массив использованных столбцов сортируется, нулевые
   значения отбрасываются, а ненулевые элементы записываются в `C`.

Схема в псевдокоде:

```text
for i in [0 .. m):
    used_cols.clear()
    for each a(i, j) in row A[i]:
        for each b(j, k) in row B[j]:
            if mark[k] != i:
                mark[k] = i
                accum[k] = a(i, j) * b(j, k)
                used_cols.push_back(k)
            else:
                accum[k] += a(i, j) * b(j, k)

    sort(used_cols)
    for k in used_cols:
        if accum[k] != 0:
            append (k, accum[k]) to row C[i]
```

Такая схема позволяет выполнять только полезные операции над ненулевыми
элементами и не требует перехода к плотному представлению матриц.

## 4. Схема распараллеливания

### SEQ

Базовая последовательная реализация. Результат формируется сразу в выходной
матрице `c_`.

### OMP (OpenMP)

Параллелизация выполнена по строкам матрицы `A`:

- директива `#pragma omp for` распределяет строки между потоками;
- каждый поток использует собственные буферы `row_vals`, `row_mark`,
  `used_cols`;
- для исключения гонок данные результата сначала собираются в построчные
  временные контейнеры `row_values` и `row_cols`;
- после завершения параллельной области матрица `C` собирается последовательно.

### TBB (Intel oneAPI TBB)

Параллелизм реализован через `tbb::parallel_for` и
`tbb::blocked_range<int>`:

- строки матрицы делятся на блоки размера `grain_size`;
- локальные рабочие буферы хранятся в
  `tbb::enumerable_thread_specific<RowWorkspace>`;
- после локального накопления каждая строка результата сохраняется в
  отдельные контейнеры, а затем последовательно компонуется в `CRS`.

### STL (`std::thread`)

Распараллеливание реализовано вручную через `std::thread`:

- сначала для каждой строки оценивается приблизительная трудоемкость
  `BuildRowCosts`;
- по накопленной стоимости вычисляются границы диапазонов строк
  `BuildThreadBoundaries`, что дает более ровный баланс нагрузки, чем простое
  деление “по числу строк”;
- каждый поток работает со своим `Workspace` (`accum`, `marks`,
  `touched_cols`);
- затем результат последовательно собирается в выходной `CRS`.

### ALL (MPI + OMP)

Гибридная реализация сочетает межпроцессное и внутрипроцессное распараллеливание:

- матрица `B` полностью рассылается всем рангам через `MPI_Bcast`;
- матрица `A` не дублируется полностью, а делится по строкам между MPI-процессами;
- границы разбиения вычисляются на ранге 0 с учетом числа ненулевых элементов,
  а не только по количеству строк, что уменьшает дисбаланс;
- строки `A` передаются ранкам через `MPI_Scatterv` в виде длин строк,
  столбцовых индексов и упакованных комплексных значений;
- внутри каждого ранга локальный блок строк умножается с использованием
  `OpenMP`;
- результат собирается на ранге 0 через `MPI_Gatherv`, восстанавливается в
  формат `CRS` и затем рассылается всем процессам, чтобы `PostProcessingImpl`
  возвращал одинаковый `OutType`.

| `common/include/common.hpp` | — | `MatrixCRS`, `InData`, `OutData` |

Ключевые особенности реализации:

- во всех версиях используется один и тот же формат `MatrixCRS`;
- временные буферы строки имеют длину `b.cols` и позволяют быстро накапливать
  частичные суммы;
- во всех параллельных реализациях сборка `CRS` выполнена в два этапа:
  локальное формирование строк и финальная последовательная компоновка;
- в `STL` реализована ручная балансировка нагрузки по стоимости строк;
- в `ALL` комплексные значения передаются между MPI-процессами в упакованном
  виде как массив `double`, что упрощает коллективные передачи.

**Граничные случаи:**

- при несовместимых размерах матриц `ValidationImpl()` возвращает `false`;
- при пустом результате корректно формируются `row_ptr`, `col_index`, `values`;
- при `m == 0` или `p == 0` параллельные реализации завершаются без ошибок.

Замеры выполнялись в release-конфигурации фреймворка PPC.

  распределением по вещественной и мнимой части.

## 7. Результаты и обсуждение

### 7.1 Корректность

Корректность проверяется функциональными тестами на нескольких наборах данных:

- `3 x 3` фиксированный пример `SmallFixed`;
- случайные разреженные матрицы размеров `10`, `20`, `30` с разной плотностью.

Для проверки формируется плотный эталонный результат `DenseMul`, который затем
преобразуется в `CRS` и сравнивается с результатом каждой реализации через
`EqualCRS`.

Тесты используют детерминированную генерацию входа, поэтому одинаковые параметры
всегда дают одинаковые матрицы, что особенно важно для `ALL` и для стабильности
производительных замеров.

### Анализ результатов

**OMP.** На данной конфигурации OpenMP показывает нестабильное масштабирование:
лучшее время достигается на `16` потоках, но выигрыш относительно `1` потока
невелик. Это указывает на то, что накладные расходы OpenMP и особенности
распределения строк оказывают заметное влияние на итоговое время.

**TBB.** Показал лучшие результаты среди всех shared-memory реализаций.
Наилучшее время достигается на `8` потоках, после чего наблюдается насыщение.
Это хорошо согласуется с использованием `parallel_for` и thread-local буферов
без лишней синхронизации.

**STL.** Реализация на `std::thread` показывает результат, близкий к `TBB`, и
также хорошо масштабируется до `8–16` потоков. Этому способствует ручная
балансировка нагрузки по стоимости строк, а не только по их индексам.

**ALL.** Гибридный вариант показывает наилучшее время на конфигурации `2`
процесса / `2` потока, после чего рост числа MPI-процессов начинает ухудшать
результат. Причина состоит в росте стоимости межпроцессного обмена
(`Scatterv`, `Gatherv`, `Bcast`) и в дополнительных накладных расходах
гибридной схемы. Таким образом, для данной размерности задачи `ALL` уступает
лучшим shared-memory реализациям, но остается корректной и демонстрирует
реальную схему `MPI + OMP`.

## 8. Выводы

- Реализовано умножение разреженных комплексных матриц в формате `CRS` в пяти
  вариантах: `SEQ`, `OMP`, `TBB`, `STL`, `ALL`.
- Все реализации используют одну и ту же математическую схему умножения и
  выдают согласованный результат.
- Наилучшую производительность показала `TBB`-версия.
- `OMP` и `STL` также обеспечивают устойчивое ускорение по сравнению с
  последовательной реализацией.
- Гибридная `ALL`-версия корректна и отражает реальную схему `MPI + OMP`, но
  для рассматриваемого размера задачи накладные расходы коммуникаций не
  позволяют ей обогнать лучшие shared-memory реализации.
- Дополнительно были стабилизированы functional/perf-тесты за счет
  детерминированной генерации входных данных, что улучшило воспроизводимость
  результатов и упростило проверку `MPI`-сценариев.

## Приложение (фрагменты кода)

### Накопление строки результата

```cpp
for (int ak = a.row_ptr[row_index]; ak < a.row_ptr[row_index + 1]; ++ak) {
    const int b_row = a.col_index[ak];
    const auto a_val = a.values[ak];

    for (int bk = b.row_ptr[b_row]; bk < b.row_ptr[b_row + 1]; ++bk) {
        const int col = b.col_index[bk];
        const auto product = a_val * b.values[bk];

        if (row_mark[col] != row_index) {
            row_mark[col] = row_index;
            row_vals[col] = product;
            used_cols.push_back(col);
        } else {
            row_vals[col] += product;
        }
    }
}
```

### OMP: параллельная обработка строк

```cpp
#pragma omp parallel default(none) shared(a, b, rows_data)
{
    std::vector<std::complex<double>> row_vals(b.cols, {0.0, 0.0});
    std::vector<int> row_mark(b.cols, -1);
    std::vector<int> used_cols;

#pragma omp for
    for (int row = 0; row < a.rows; ++row) {
        AccumulateRowProducts(row, row_vals, row_mark, used_cols);
        std::ranges::sort(used_cols);
        CollectRowValues(row_vals, used_cols, rows_data[row]);
    }
}
```

### TBB: parallel_for по диапазону строк

```cpp
tbb::parallel_for(tbb::blocked_range<int>(0, m, grain_size),
                  [&](const tbb::blocked_range<int> &range) {
    auto &local = workspace.local();
    for (int i = range.begin(); i != range.end(); ++i) {
        AccumulateRowProducts(i, local.row_vals, local.row_mark, local.used_cols);
        std::ranges::sort(local.used_cols);
        CollectRowValues(local.row_vals, local.used_cols, row_cols[i], row_values[i]);
    }
});
```

### ALL: распределение строк `A` и сборка результата

```cpp
BroadcastMatrix(b_, rank);

if (rank == 0) {
    row_bounds = BuildRowBounds(a_, size);
    nnz_counts = BuildNNZCounts(a_, row_bounds);
}
MPI_Bcast(row_bounds.data(), size + 1, MPI_INT, 0, MPI_COMM_WORLD);
MPI_Bcast(nnz_counts.data(), size, MPI_INT, 0, MPI_COMM_WORLD);

const MatrixCRS local_a = ScatterRows(a_, row_bounds, nnz_counts, rank, size);
const MatrixCRS local_c = MultiplyLocalOMP(local_a, b_);

GatherMatrix(local_c, c_, row_bounds, rank, size, a_.rows);
BroadcastMatrix(c_, rank);
```
